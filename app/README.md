# 雅砻江运维 Demo

## 首页真实地形与天空

首页采用 Google Photorealistic 3D Tiles 的雅砻江真实地形，保留电站模型和运行卡片；Three.js 场景使用 [Takram Tokyo 示例](https://takram-design-engineering.github.io/three-geospatial/?path=/story/clouds-3d-tiles-renderer-integration--tokyo)的体积云、大气散射、云影、镜头光晕、AgX 色调映射与抗锯齿流程。数据精度由 Google 在该区域的覆盖决定。

将 `.env.example` 复制为 `.env.local`，填写 `VITE_GOOGLE_MAPS_API_KEY`。Google Cloud 项目需启用 Map Tiles API，并允许本地页面来源；修改配置后重启开发服务，静态发布前重新构建。无人机航线页仍需要 `VITE_MAPBOX_ACCESS_TOKEN`。

运行 `npm install`、`npm run dev`，打开终端显示的本地地址。首页右上角可定位电站、返回初始视角、调整日期/云量/太阳时/云底海拔/曝光及切换地图全屏。“恢复 Tokyo 参数与视角”恢复整组默认值。

画面偏白时，可在“天空与光照”先把曝光从 10 降到 6–8，再降低“近地薄雾”（100% 为 Tokyo 默认，0% 关闭薄雾）。“远景大气透视”支持 0–100% 连续调节，0% 关闭远景雾感、100% 保持 Tokyo 原效果，可先试 30–50%；仅混合距离散射与透射阶段，不改变天空、地形光照和云影的强度。“恢复 Tokyo”按钮会将这两项一并复位为 100%。

参数来源为上游 `b012ad06d858` 的 Tokyo story：第 170 天、当地太阳时 07:30、云量 35%、曝光 10；相机距离 1000 m、朝向 −110°、俯仰 −9°，沿用 Canvas 的 75° 视野与 1–2 倍像素比。太阳按雅砻江经度换算当地太阳时；云采用 high 质量、速度 `[0.001, 0]`、3 级 512px 阴影、`farScale=0.25`，其余散射、密度、时域重建、光柱、湍流与阴影值直接沿用已锁定的 Takram 依赖默认值。大气使用示例同款预计算生成器并启用高阶散射；调色 LUT、深度/法线调试均关闭。

用户允许适配高原：Tokyo 参考预设将相机目标与所有云层统一上移 3500 m，参考云层海拔为 4250/4500/11000 m，保留原层厚、层间距与密度。参考目标在雅砻江 `[101.4525, 27.7458]`；各站定位使用 Tokyo 的近景相机参数，不保证同时容纳四站。相机首次拖动后启用示例的地形碰撞校正。该适配不更改电站模型高度。参考参数集中在 `src/components/geospatialPreset.js`，当前项目默认以用户保存值为准。

工具栏的“保存参数”（或模型面板“另存为新参数”）每次新增一套完整快照，包含所有电站高度、比例、朝向、天气、太阳日期/时间、曝光、薄雾、大气透视、相机精确位置/朝向/镜头、云场偏移、玻璃及全屏/主题设置。“参数列表”中可填写名称保存、来回载入、设为初始默认或删除；留空名称按保存时间命名。新增不会覆盖已有项，也不会自动改动初始默认。刷新、重启或换端口后加载指定的初始默认；载入操作也会在项目中记录最近使用的预设。删除初始默认时自动使用第一套剩余参数，删除已载入项时回到初始默认，至少保留一套。

所有操作经本机同源 `/__map-config` 接口原子写入 `src/data/mapConfig.json`，`presets.items` 保存完整快照，`defaultId` / `lastSelectedId` 记录默认与最近选择；文件顶层同步初始默认快照，兼容构建时加载。服务端对最新磁盘列表执行新增/切换/设默认/删除操作，避免旧页面整份覆盖列表。页面启动和打开列表时重新读取项目文件，开发服务及本机 preview 下均可使用；静态部署需重新构建，编辑预设需要该本机写入接口。云仍按既定风速运动，每次载入从预设偏移开始。“初始视角”返回默认预设的相机；“恢复 Tokyo 参数与视角”只修改当前预览。模型高度仍由用户手动调整，不自动贴山。

2026-09-11 保存的用户现场参数：云量 32%、太阳时 15:42、年内第 170 天（2026 年）、云底 5600 m、曝光 10、近地薄雾 100%、远景大气透视 45%；模型比例 550、朝向 135°，四站高度与相机 ECEF 数值详见配置。Tokyo 原始参考参数仍保留在 `geospatialPreset.js`，首页加载优先使用 `mapConfig.json` 中的 `geospatial`。

验证：`npm run build`、`node scripts/test-map-config.mjs`、`node scripts/test-geospatial-scene.mjs`、`node scripts/test-station-cards.mjs`、`node scripts/test-station-glass-config.mjs`、`node scripts/test-station-pbr.mjs`。

电站 PBR 材质通过 `geospatialCloudShadow.js` 接收同一套 Takram 云影，按表面位置和高度衰减太阳直射光，保留环境光、玻璃/金属反射及模型自投影。开发服务下打开 `/scripts/test-model-cloud-shadow.html` 可运行无需 Google 请求的 GPU 回归检查，验证浓云、部分遮挡、环境光和云上表面。

设备自投影使用 4096px 阴影贴图，范围随当前电站模型包围盒贴合；深度与法线偏移按阴影像素的世界尺寸计算，避免模型表面的自阴影斜纹，并随模型缩放更新。

光伏板使用光滑玻璃叠层与轻微磨砂：基底粗糙度 0.16、玻璃涂层粗糙度 0.08、IOR 1.5，保留电池片图案与细节。`skyReflectionProbe.js` 从最近电站位置采样同一套天空、体积云、太阳和天气偏移，以 256px 六面 HDR 反射及 PMREM 过滤提供真实天空反射；分六帧更新，约每 1.5 秒完成一轮，仅应用于光伏板。`/scripts/test-sky-reflection.html` 验证云量变化确实进入 GPU 反射贴图。

天空和模型面板的数值均可直接输入，输入有效值即时预览，Enter 确认且不触发参数保存；清空后失焦恢复有效值，超出范围时失焦限制到边界。滑块按住 Shift 拖动为正常速度的 1/10，并提供更细步进，拖动中可随时按下或松开 Shift。方向键调整，Shift + 方向键微调。云量/薄雾/大气透视输入百分数，太阳时输入十进制小时（15.5 = 15:30）；保存仍通过“保存参数”写入项目。开发服务下 `/scripts/test-scene-parameter.html` 检查数值输入、慢速拖动、键盘和边界行为。
