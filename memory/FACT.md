# 项目记忆：雅砻江运维首页渐进换肤

状态：已确认

适用范围：整个 `0903-雅砻江运维` 项目，首个试点为首页。后续页面和功能默认继承本文件，除非用户明确提出新的结构或交互目标。

## 核心目标

以换肤前的首页作为内容结构基线。换肤后必须保持以下内容不变：

- 模块和区域的组成
- 字段、标签、指标和文案
- 内容数量和展示顺序
- 数据来源及数据语义
- 路由、交互入口和操作路径

换肤允许调整的范围只有视觉语言：

- 颜色、字体和数字字体
- 表面层级、分隔线和透明度
- 边框、圆角和阴影
- 间距、尺寸和响应式呈现
- 进入、悬停、选中、加载等动效

间距和尺寸可以优化密度，但不能借此隐藏、删减、重排或替换业务内容；只有本文件“已确认的首页视觉决策”中列出的例外可以执行。

## 本轮更新目标

1. **全局 token 化**：把颜色、表面层级、文字、边框、圆角、间距、尺寸和动效整理为可复用的语义 token。
2. **合并相似语义**：相同用途的颜色和层级只保留一个 canonical token，hover、soft、foreground 等状态优先由基础 token 派生，不为单个组件复制近似颜色。
3. **引入 HeroUI 作为整理参考**：借用 HeroUI 的语义 token 思路和组件分类，帮助建立项目自己的 `--ops-*` 体系；不因引入参考体系而改变现有业务结构。

## 已确认的首页视觉决策

以下是用户已经明确确认的视觉处理，视为换肤基线的一部分：

- KPI 内容保持原有七项和原有顺序，继续单行展示；每项恢复为独立卡片并保留卡间留隙。
- Agent 内容保持原有数量和顺序；每个 Agent 恢复为独立卡片并保留卡间留隙。
- 首页左上角的 `BASIN OPERATIONS / 流域运行态势 / 在线状态` 标题行不渲染。
- Agent 区的 `AI ORCHESTRATION / 智能体协同 / 执行状态` 标题行不渲染。
- 地图作为数字孪生模块的大背景，顶部工具条和底部时间轴覆盖在地图上，并使用可读的毛玻璃表面。
- 以上处理不改变 KPI、Agent、地图和时间轴中的业务数据、数量、顺序或操作路径。

地图模块和 3D 场景模块不参与本轮换肤重构。允许调整地图外层的视觉包裹（例如透明度、模糊、浮层表面和间距），但不得改变：

- Mapbox/3D 的生命周期、图层、数据绑定和相机行为

- 3D 模型、场景 JSON、资源预加载和嵌入式电站监视器

具体冻结文件和目录以根目录 `AGENTS.md` 为准。

## HeroUI 采用决策

HeroUI 当前作为设计系统参考和渐进适配方向，而不是一次性重写方案。官方文档显示，HeroUI v3 使用 CSS 变量和 BEM 类组织主题，组件建立在 React Aria 上，快速开始要求 React 19+ 与 Tailwind CSS v4：

- [HeroUI 组件目录](https://heroui.com/en/docs/react/components)
- [HeroUI 主题系统](https://heroui.com/en/docs/react/getting-started/theming)
- [HeroUI 颜色语义](https://heroui.com/en/docs/react/getting-started/colors)
- [HeroUI 快速开始](https://heroui.com/en/docs/react/getting-started/quick-start)

当前项目已有 React 19 和大规模现有 CSS，现已接入 Tailwind CSS v4 与 HeroUI v3.2.4 的选择性样式和通用控件。因此后续仍采用渐进适配顺序：

1. 先用 HeroUI 的语义角色和组件分类审计、合并现有 `--ops-*` token。
2. 保留 `--ops-*` 作为本项目的 canonical token，不让第三方命名直接覆盖业务语义。
3. 对新增或普通通用控件做局部 HeroUI 试点，验证样式隔离、主题、无障碍和包体。
4. KPI、Agent、AI 对话、时间轴、地图浮层和 3D 场景继续使用项目域组合；地图/3D 不做 HeroUI 替换。

## 新页面和新功能的工作顺序

1. 先阅读本文件和 `memory/DESIGN_TOKENS.md`。
2. 以换肤前版本核对内容结构、字段、数量、顺序和交互路径。
3. 把需求拆成“视觉变化”和“结构/行为变化”；默认只实施前者。
4. 复用现有 token 和组件，避免在页面中新增一套平行视觉语言。
5. 若必须改变结构或行为，先向用户列出具体变化点并获得确认。
6. 完成后验证深色/浅色主题、关键宽度和构建结果。

## 推送 GitHub 前保存地图参数

- 每次推送 GitHub 前，必须执行一次“保存参数”，将当前地图完整配置写入 `app/src/data/mapConfig.json`；不能仅依赖自动保存或浏览器缓存。
- 保存范围包括所有电站的显示比例、水平朝向、离地高度、自发光、材质颜色、镜头03机位、太阳方位角和高度角、光照时段、图层开关、平面/3D 模式及玻璃参数。
- 镜头03应保留用户已保存的机位，不得擅自用临时浏览视角覆盖；用户明确要求更新镜头03时，先保存当前机位到镜头03，再保存完整配置。
- 确认保存成功，并核对磁盘配置与当前设置一致；配置发生变化时，将其纳入本次提交后再推送。保存失败或无法确认时，不得声称已保存，不得用旧默认值覆盖当前参数，须先解决问题再推送。
