# 全局 HeroUI 与 Token 重构计划

## 目标

在不改变换肤前首页及其他页面的业务内容、布局骨架、数据顺序和交互路径的前提下，引入 HeroUI v3 作为通用控件和语义 token 的实现基础，合并重复的项目视觉变量。地图、3D 场景及其内部生命周期保持冻结。

## 阶段

1. **基座**：锁定 HeroUI/Tailwind 版本，接入 Vite 插件和无全局 preflight 的 HeroUI 组件样式，建立 `--ops-*` 到 HeroUI 语义变量的映射。
2. **控件迁移**：按重复度迁移分段选择、按钮、图标按钮、输入/筛选等通用控件；保留业务组合 DOM、文案、状态和回调。
3. **回归**：构建并检查首页、工作台、工单/告警页的深浅主题、焦点/悬停/禁用态和关键宽度；确认地图/3D 几何与控制台无回归。

## 验收

- `npm run build` 通过。
- 1180px 和 1440px 下主要页面无横向溢出或结构位移。
- HeroUI 组件类和语义变量实际生效，旧的相似 token 不再新增。
- 地图、3D、数据字段、数量、顺序和操作路径不变。

## 风险

- 旧 CSS 为非 layer 规则，可能覆盖 HeroUI layered CSS；迁移控件使用局部兼容规则。
- 完整 HeroUI preflight 会影响既有页面，因此首阶段只引入主题、组件、utilities 和 variants 样式，不启用全局 reset。
